# 对话内按需配置 · 明确连接器指令 v6

本版接续[多设置接入设计 v5](conversational-settings.v5.md)。实测发现：上一轮连接器提案的文字会留在模型上下文中；当连接器后来又被关闭，用户明确说“帮我打开 PubMed 工具”时，模型可能只复述旧提案，未调用新工具，因而没有卡片。旧提案即使处于 `applied`，也不代表当前有效配置仍包含该连接器。

## 确定性入口

- 对**完整、无歧义的启用指令**，在进入模型运行前由后端根据已安装连接器 ID 与展示名解析目标，例如“请在当前会话启用 PubMed”“帮我打开 PubMed 工具”和“Enable PubMed connector”。不对一般研究问题、“不要启用”等否定指令或包含其他任务的复合请求进行猜测。
- 目标已启用时直接返回当前状态；目标已安装但不可用时说明原因。目标可用且尚未启用时，持久化与 Agent 工具相同的会话级待确认提案并展示卡片。只创建提案，绝不代用户确认。
- 相同会话和连接器的待确认提案应复用。旧提案已应用但当前设置后来又关闭时，允许新建提案；不能依据历史聊天文字或历史 `applied` 状态阻止新请求。
- 前端只在服务端明确处理该指令时跳过模型运行；否则保留现有 Agent 提议流程。纯配置指令不作为研究任务自动执行，确认后无需自动发起无目标运行。

验收：在已配置真实 LLM 的会话，关闭 PubMed 后输入“帮我打开 PubMed 工具”，无需模型选中工具也能看到新卡片；确认后仅当前会话启用 PubMed。再次输入同一指令应提示已经启用，不再生成卡片；否定句与一般检索任务不得触发确定性入口。
