# 对话内配置：连接器任务接续与 PubMed 自动应用切片 v7

依据[交互设计 v7](conversational-settings.v7.md)与[开发规格 v2](conversational-settings-development.v2.md)，本切片在 v6 明确连接器指令上增加以下实际行为。

- Agent 在真实任务运行中提出一个连接器启用请求后，完成本轮工具与消息持久化，源 run 以 `interrupted` 结束。配置卡仍等待确认；源运行不继续占用执行资源。纯配置指令仍使用 `user-request:*`，确认后只更改设置，不发起无目标运行。
- 用户确认后，服务端用请求 ID 派生固定的后续 run ID，在同一 run 文件修改屏障内查找或创建关联 run。后续 run 沿用源 run 的冻结设置，只加入获准连接器；内部配置通知触发 Agent 读取之前的会话和工具结果继续任务，不向对话伪造一条用户输入。重复确认和服务重启会复用同一后续 run。
- 会话新增默认关闭的独立授权 `autoApplyLowRiskConfiguration`。目前白名单只含已安装且就绪的公开 PubMed 连接器。提案创建时若授权开启，记录 30 秒后到期时间；用户可在卡片中拒绝。服务端定时器到期时复核授权、连接器、配置基线和当前运行状态，复用人工确认服务提交并创建接续；浏览器关闭不影响服务端计时。关闭授权会撤回待确认请求的自动到期时间。
- 提案保存会话 Stop generation；Stop 会将任务中的未决提案置为 `stale`，即使后来又提交新任务，也不会把旧提案重新自动应用或接续。
- 卡片显示倒计时，自动应用后的会话刷新会读取配置结果和关联运行。旧提案若连接器随后被关闭，仍可按 v6 规则新建请求。

当前仅覆盖已安装连接器的会话级 `connector.enable`。模型凭据、新连接器、全局设置和其他能力仍要求单独设计及实现。后续运行使用源运行的持久会话历史与工具结果；对于已执行但外部结果未知的动作，模型被要求先核实再重试，不能把这视为通用外部副作用的强幂等保证。开发规格 v2 中更完整的通用安全检查点与 outbox 故障注入仍是后续工作。
