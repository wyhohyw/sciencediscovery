# 对话内配置：原任务持久暂停与同 run 恢复 v8

本切片落实[交互设计 v10](conversational-settings.v10.md)及[开发规格 v3](conversational-settings-development.v3.md)在**原生 Agent 执行器**中的连接器启用流程。旧记录与 JiuwenSwarm 后端仍保留 v7 的关联 run 接续方式。

## 已实现

- Agent 提出连接器启用请求后，运行时完成当前工具批次、提交模型历史，调度器写入不可变 `ConfigurationCheckpoint` 记录，并将原 `SessionRun` 标为非终态 `blocked/configuration_wait`。只有检查点和状态都已提交，待确认卡片才对前端可见。此时不写最终助手答复，不发 `run.completed`。
- 人工确认、人工拒绝及已单独授权的低风险到期自动应用，都将**原 run ID**重新入队。恢复从检查点模型历史继续，注入配置决定；确认时仅将获准连接器加入该 run 的冻结设置，并重新构建工具。拒绝时 Agent 可选择替代路径或给出受限结果。原用户消息不重复创建。
- 后续用户消息排在等待配置的 run 后面；其入队不会使待确认请求的 Stop generation 失效。Stop 可取消配置等待并使旧请求失效。服务重启保留等待状态，重复确认不会创建另一个 run 或另一条配置通知。
- 确认/拒绝后的卡片折叠为一行可展开回执；运行中的普通工具权限等待不再被误认为配置等待。旧关联 run 记录继续可读。

## 范围与后续工作

此机制目前只针对原生执行器的会话级、已安装连接器启用请求。JiuwenSwarm 尚未接入运行时暂停钩子，因此仍使用 v7 接续。模型密钥、新连接器安装、全局设置和其他设置类型尚未接入该机制。

检查点在工具批次完成后保存历史，能避免恢复时重放已提交的工具结果；但尚无针对所有外部副作用的通用 outbox/不确定提交隔离协议。配置变更、恢复入队和通知分别持久化并做幂等处理，尚未合并为跨存储事务。涉及未知副作用的任务仍须单独验证。
