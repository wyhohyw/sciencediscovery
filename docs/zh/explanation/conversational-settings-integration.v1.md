# 对话内配置：首个真实接入切片

> 当前交互与验收步骤见 [接入切片 v2](conversational-settings-integration.v2.md)；本文件保留首次实现状态。

本分支从主仓 `main` 的 `7defad5d` 建立，依据同目录的《对话内配置设计》和《开发文档》接入真实 ScienceDiscovery。当前完成的是 **缺少任务模型时的模型选择与连接**，不是设计文档中所有设置类别的完整实现。

## 已接入的流程

1. 当前会话没有任务模型时，对话区展示配置卡，说明原因、模型注册位置、使用范围和下一步动作。用户可以暂不配置。
2. 已有模型时，用户在卡片内选择并确认，也可选择“连接新模型”；新模型复用现有服务商连接向导，填写 API Key 或自定义服务端点。向导临时创建服务商和首个模型，真实连接测试通过后保留；失败时尽力回滚。凭据通过配置 API 处理，不写成聊天消息。
3. 模型只绑定当前会话。内联连接新建首个模型时，不自动修改全局默认模型。若输入框中已有草稿，模型生效后经正常消息提交路径继续运行。
4. UI 分别显示“模型已用于当前会话”和“草稿已提交/提交失败”。连接成功但会话绑定失败时保留重试入口。
5. 本地免密服务商的连接测试允许不带 Authorization 头；需要密钥的服务商仍在发起网络请求前拒绝空密钥。

## 当前边界

- 触发条件只覆盖缺少会话任务模型；尚未实现 Agent 对 MCP、Runner、权限等其他配置的主动提案。
- 卡片与回执是前端状态，刷新后不会恢复提案历史。尚无服务端提案记录、修订号 CAS、统一配置计划或事务式提交。
- 现有连接向导仍是分步注册与尽力回滚，不能视为设计文档要求的原子配置事务。
- 草稿继续提交依赖当前浏览器页面；中途切换会话、修改草稿或刷新页面时，不会自动发送旧草稿。
- 本地联调用的模型服务只用于验证配置链路和任务提交，不代表真实大模型质量或生产连通性。

## 本地验收

隔离运行目录：`/root/sciencediscovery-conversational-settings`（WSL）；服务端口：`4410`，Runner：`4411`。在全新数据目录中启动后：

1. 新建项目，打开自动创建的会话；应直接看到对话内配置卡。
2. 在输入框写一条任务草稿；卡片应说明确认后会提交草稿。
3. 在卡片内连接一个可用服务商，或填入自定义 OpenAI 兼容接口及模型标识；确认连接测试通过。
4. 检查当前会话绑定了模型、草稿只提交一次、运行状态与回执分别可见；检查全局默认模型保持原值。
5. 新建无模型会话，选择已有模型并确认；检查只有该会话的模型设置变化。

覆盖的核心测试：模型连接向导、对话卡、免密连接测试、会话作用域注册，以及工作区构建。
