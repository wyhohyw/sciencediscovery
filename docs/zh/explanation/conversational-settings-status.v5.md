## 1. 当前可以配置什么

| 能力 | 当前实现 | 范围与限制 |
|---|---|---|
| 选择已有模型 | 对话中的模型卡可以选择、绑定模型 | 绑定当前会话；有可继承的默认模型时直接使用，不重复要求配置 |
| 首次接入模型 | 无已登记模型时，卡片展示服务商连接向导，复用连接验证与后端凭据存储 | 首个模型成为全局默认；已有模型时也可连接另一个，不能统称为所有变更都只影响当前会话 |
| 启用已安装连接器 | 主 Agent 可提议启用当前会话尚未启用、已安装且就绪的连接器，用户通过卡片确认 | 只增加获准的会话连接器；不负责安装新连接器或填充缺失凭据 |
| 原任务暂停与恢复 | 原生 Agent 执行器保存持久检查点，确认或拒绝后恢复同一个 run | 目前针对上述连接器启用流程；不等于任意模型或任意设置都能在任务中热切换 |
| 低风险到期自动应用 | 独立授权开启后，符合条件的 PubMed 请求可在 30 秒后由服务端应用 | 默认关闭；当前白名单只有 PubMed；工具调用仍有自己的权限策略 |

尚未接入通用对话配置的包括：模型凭据修复、新增 HTTP/SSE MCP、OAuth、代理、超时、Runner 等设置。配置文件路径、任意 REST API、STDIO 启动等也不能只给 Agent 一个字符串就自动完成接入。

## 2. 卡片什么时候出现

进入空会话不会自动展开完整配置卡。模型缺失时保留输入区的手动配置入口，用户提交需要模型的任务后再按需引导。

连接器有两条入口：

1. **独立启用指令**，例如“帮我打开 PubMed 工具”：浏览器调用服务端配置预检，解析已安装目录中的唯一目标。它直接创建待确认提案，不需要先跑 LLM，也不创建没有研究目标的后续任务。已启用时返回当前状态。
2. **研究任务中的需求**：主 Agent 判断需要未启用连接器时，调用 `propose_connector_enable`。复合研究请求不走上述简单指令解析；是否提出配置请求仍与模型的工具选择有关。

子 Agent / Specialist 可以按既有规则获得自己的预设连接器。主 Agent 也可能选择委派任务；因此，没有配置卡不能单凭现象判定为识别失败，还要检查具体由谁调用了什么工具。要单独验证主 Agent 的配置链路，应明确要求不使用子 Agent。当前提案工具只提供给主 Agent，未实现所有子 Agent 共用的配置提案机制。

## 3. 确认之后怎样继续

原生执行器的连接器流程为：

1. 主 Agent 提案；运行时在当前工具批次完成后保存模型历史检查点。
2. 原 run 进入非终态的 `blocked/configuration_wait`；检查点提交后才显示可确认卡片。此时不写最终助手答复。
3. 用户确认后，只把获批准的连接器加入该 run 的设置快照，重新装配工具，从同一 run 的检查点继续。无需再发“继续”。拒绝结果也交回原 run，由 Agent 选择替代路径或说明限制。
4. 已处理卡片默认折叠为一行可展开的只读回执，例如“PubMed 已启用 · 仅当前会话”。点击可查看详情，不重复显示确认按钮。
5. 连接器调用若另需授权，会出现独立的工具权限卡；允许后继续。配置已保存、工具已获授权、任务已完成是三个不同状态。

Stop 可终止等待并阻止旧请求唤醒任务。重复确认不会创建第二个任务。JiuwenSwarm 和旧记录仍采用关联后续 run 的方式，不能把它们描述为已经支持同一 run 暂停恢复。

## 4. 长任务与 30 秒自动应用

“Always allow”是工具权限设置，不自动授予配置修改权。会话中另有默认关闭的“自动应用低风险会话配置”授权。

当前只有已安装、就绪且满足检查条件的 PubMed 请求属于白名单。开启独立授权后，卡片提供 30 秒缓冲和取消入口；到期由服务端复核授权、设置基线、连接器状态及任务/Stop 状态，再应用并恢复任务。关闭授权、取消或条件失效会阻止自动应用。

模型连接、密钥、OAuth、全局设置等不能因等待 30 秒就自动获准。30 秒机制已接入当前切片，但不属于下述人工确认真实模型用例的实测结论。

## 5. 通用机制已经做到哪一步

目前可以复用的是连接器提案持久化、卡片和折叠回执、决定接口、会话配置提交、检查点与调度恢复。新增一个同类的“启用已安装连接器”能力，可以复用这条链路；自动应用白名单仍需逐项审查。

| 当前接口或实体 | 用途 |
|---|---|
| `propose_connector_enable({ connectorId })` | 主 Agent 登记提案，不具有批准能力 |
| `POST /api/sessions/:sessionId/configuration/preflight` | 处理独立、无歧义的连接器启用指令 |
| `GET /api/sessions/:sessionId/configuration-requests` | 恢复会话中的配置请求与状态 |
| `POST /api/sessions/:sessionId/configuration-requests/:requestId/decision` | 人工应用或拒绝提案 |
| `ConfigurationCheckpoint`、`configurationResume` | 持久保存上下文并恢复原 run |

v1 开发规格中的通用能力目录、schema 驱动表单、适配器协议、通用预览/应用接口属于目标架构，尚未完整实现。增加新的设置类型，仍要定义该领域的输入、验证、凭据通道、作用范围和生效方式，不能声称只注册一个字段就能安全配置全部设置。

## 6. 已完成的真实端到端验证

2026-10-16 在隔离的 `4410` 服务上，使用真实 DeepSeek-V4.1-Flash 模型，已验证以下限定场景：

- 会话原先仅启用 Web；主 Agent 主动调用 `propose_connector_enable(pubmed)`。
- 原 run 进入配置等待，确认前没有最终答复；确认的 `continuationRunId` 与原 run ID 相同。
- 确认后调用一次 `mcp__pubmed__search`，参数 `limit: 3`；另行批准 `pubmed:search` 工具权限。
- 原 run 最终完成，回复包含 3 篇文献的标题、年份和 PubMed 链接。事件中没有子 Agent 或 shell 调用。
- 测试项目与会话已清理，未修改原有用户会话。

### 复现步骤

1. 在运行此隔离分支的服务中新建会话，选择真实模型，确认当前会话尚未启用 PubMed 且连接器已安装、就绪。
2. 发送下面的限定提示词。
3. 确认配置卡；若随后出现 `pubmed:search` 工具权限卡，再允许本次调用。
4. 观察同一任务继续，配置卡折叠为回执，最终出现带来源的答复。

```text
必须使用 PubMed 检索 TP53 相关文献。只检索一次，最多取 3 篇 2024 年以来的文献，给出每篇的标题、年份和 PubMed 链接，并用一句话概括共同研究方向。请由主 Agent 自己完成，不要委派或调用任何子 Agent，也不要运行 shell 或代码。如果 PubMed 尚未启用，请在对话中请求启用；确认后继续完成同一任务。
```

如果会话已经启用 PubMed，不再弹配置卡是正常行为。独立输入“帮我打开 PubMed 工具”可验证直接配置入口，但不能用它证明研究任务的暂停与恢复。

### 验证边界

不限篇数的宽泛 TP53 研究题曾触发约 250 篇文献的检索，随后模型尝试用 shell 查找过大的工具输出；该次运行被停止，未验证最终报告完成。限定三篇的成功不代表宽题、大工具输出或所有模型行为都已解决。

同一 run 恢复也不等于已经实现所有外部副作用的通用事务保障：跨存储 outbox、不确定提交隔离等仍见集成范围 v8 中的后续工作。本文没有把重启、拒绝、Stop、30 秒自动应用等所有设计验收项都列为这次真实模型测试已通过。
